# Punit v0.1.0-alpha (pre-release)

> [!WARNING]
> **Experimental alpha. Not for production OTA delivery.**
> Punit has been **tested internally only**. It has **not** been validated at production scale
> and has **not** had an independent security audit. Do not use it to ship updates to real
> users until you have independently validated its security, reliability, compatibility,
> rollback, signing and recovery for your apps. You use it **at your own risk** (Apache-2.0,
> no warranty).

Punit is a **self-hosted** over-the-air patch platform for Flutter apps. **No hosted Punit
service exists.** You run the server and keep the signing key.

> [!NOTE]
> **Testing status.** Tested internally on **Linux** (development machine and Docker backend)
> and with **Android** Flutter apps on a small number of devices. **iOS, macOS and Windows are
> not tested.** Android testing does not establish compatibility with every Android device, OS
> version, CPU architecture (ABI) or Flutter version.

| Platform | Status |
|---|---|
| Linux development environment | Internally tested |
| Android Flutter application | Internally tested |
| iOS | Not tested |
| macOS | Not tested |
| Windows | Not tested |

## Highlights

- **Signed patches:** ES256 over a canonical message (app, release, patch number, platform,
  arch, format, hashes, size). Verified on the device with a key compiled into the app, plus
  SHA-256 and size checks.
- **Release-bound patches** with **channels** (`dev` / `staging` / `production`),
  **deterministic percentage rollouts**, **rollback** and permanent **revoke**.
- **Boot protection:** a patched app that fails to start falls back to the last good code by
  itself.
- **Control plane / data plane split:** FastAPI answers small update checks, and patch bytes
  come straight from nginx/CDN or S3-compatible storage.
- **Flutter client package** `ota_client`, with an example app.
- **Experimental Android Dart code patches** on stock Flutter (`ota release android` /
  `ota patch android`). Check the store-policy notes first.
- **Local self-hosted stack** with one-command setup and an end-to-end verification script.

## Quickstart

Requires Docker with Compose v2, Bash and curl. Tested on Linux only.

```bash
git clone https://github.com/punitsoni22/flutter_ota_system.git && cd flutter_ota_system
cp .env.example .env
./scripts/setup_local.sh
./scripts/seed_demo.sh
./scripts/publish_test_patch.sh
./scripts/verify_demo.sh     # ends with: RESULT: all checks passed
```

Then run `example_app` against it (see the README).

## What was tested for this release

- `scripts/verify_demo.sh` on Linux + Docker Engine: health, DB connectivity, device
  registration, update check, CDN download, SHA-256, independent ES256 verification, rejection
  of corrupted files, tampered signatures and substituted metadata, anti-replay, rollback,
  revoke.
- Backend unit/integration tests (pytest, SQLite).
- `ota_client` unit tests and static analysis (Flutter 3.44 stable); `example_app` analysis.
- Android behaviour: manual internal testing by the maintainers on a small number of devices
  over USB: `mock-v1` config patches (download, verify, stage, activate after restart, crash
  fallback, rollback, revoke, server down) and Android code patches (`ota release android` /
  `ota patch android`, crash fallback, rollback, store-policy gate, refusal of asset changes).
  No public device matrix yet.

**Not tested:** production deployments at scale, load/soak tests, iOS (no builds or devices;
needs macOS + Xcode), macOS and Windows development machines or Docker hosts, Android device /
OS-version / ABI compatibility beyond the few devices used, Flutter versions other than the
ones the maintainers used, long-running upgrades between versions.

## Known limitations

- Single shared admin API key; no users/roles, no **audit log**.
- Open device registration and no rate limiting.
- Signing key lives in a PEM file or an env var. There is no Key Vault/KMS/HSM signer and no
  key-rotation tooling.
- Storage: local disk + nginx, or S3-compatible. **No Azure Blob adapter. Redis is not used.**
- Patch URLs are public and permanent (content-addressed); there are no short-lived URLs.
- No iOS code patches (not implemented), and iOS is not tested at all. Android code patches depend on Flutter internals and need a new store
  release for every Flutter upgrade.
- APIs, database schema and patch formats may change before 1.0.

## Security

Read `docs/security.md` before deploying anything. **Report vulnerabilities privately** through
GitHub's *Report a vulnerability* (Security tab), as described in `SECURITY.md`. Never use
public issues for them.
