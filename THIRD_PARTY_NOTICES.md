## 7. Future actions before publishing pre-built Docker images

Flutter OTA System v0.1.0-alpha.1 publishes **source code only**. Users build images locally from
`backend/Dockerfile` and pull the base images themselves, so the duties below do not apply yet.
**Before anyone pushes a Flutter OTA System image to a registry (Docker Hub, GHCR, ACR, ...), do all of these:**

| # | Component in the image | Licence | Action required |
|---|---|---|---|
| 1 | psycopg, psycopg-binary | LGPL-3.0-only | Ship the LGPL-3.0 and GPL-3.0 texts in the image (e.g. `/usr/share/licenses/flutter-ota-system/`). State which psycopg version is included and where its source is. Keep it a normal, replaceable pip package (do not merge it into other files), so users can swap in their own build |
| 2 | libpq, OpenSSL and other libraries bundled in the `psycopg-binary` wheel | PostgreSQL Licence, Apache-2.0, others | Copy the licence files shipped inside the wheel into the image |
| 3 | `python:3.13-slim` base (Debian) | PSF-2.0 + many Debian package licences, including GPL/LGPL | Keep `/usr/share/doc/*/copyright` in the image (do not strip it). For GPL packages, be able to point to the matching Debian source (the image tag and digest identify it) |
| 4 | All Python packages in the image | see sections 2 and 3 | Generate a licence report at build time (`pip-licenses --with-license-file`) and include it in the image |
| 5 | Flutter OTA System itself | Apache-2.0 | Include `LICENSE`, `NOTICE` and this file in the image |
| 6 | Images we do not build (`postgres`, `nginx`, `caddy`) | their own | Only reference them by tag; do not re-publish them under the Flutter OTA System name |
| 7 | Whole image | — | Generate an SBOM (for example `syft` or `docker sbom`), publish it with the image, and add OCI labels `org.opencontainers.image.licenses="Apache-2.0"` and `org.opencontainers.image.source` |

Add a row to [docs/release/PREPUBLISH_CHECKLIST.md](docs/release/PREPUBLISH_CHECKLIST.md) when this
becomes relevant.
