# Flutter OTA System demo app

The official demo app of [Flutter OTA System](../../../README.md) and the `flutter_ota_system`
package. It is the **only** demo app in the repository.

It shows how a real feature is patched over the air on Android: a products screen that loads
JSON over HTTP, with a freezed model, an entity, a repository, a controller and a UI. The demo
patch changes all of them (new API endpoint, new `rating` field, new UI). The phone runs the new
code after a restart, without a reinstall.

It was tested this way on one Android 13 arm64 phone (experimental alpha; see
[limitations](../../../docs/limitations.md)).

## Run the demo

You need the `flutter_ota` CLI, a toolchain, a running server and a phone connected over USB. See
the [quick start](../../../docs/quick-start.md) for the one-time setup (server, `flutter_ota init`,
`config`, `toolchain install`, `keys init`).

```bash
cd packages/ota_client/example

# 1. The demo's product API (v1 and v2), reachable from the phone over USB.
./demo_api/serve.sh &                       # http://127.0.0.1:8090
adb reverse tcp:8090 tcp:8090
adb reverse tcp:8000 tcp:8000               # your local OTA server, if it runs on this computer

# 2. Store release, then install it (a test install; a real app goes to the store).
flutter_ota doctor
flutter_ota release android --kind apk
adb install -r build/app/outputs/flutter-apk/app-release.apk
# The app shows "Products (v1)" and "active patch: none (store code)".

# 3. Change the feature: new endpoint, new `rating` model field, entity, repository, UI.
cp -r demo_patch_v2/products/. packages/products/
(cd packages/products && dart run build_runner build --delete-conflicting-outputs)

# 4. One command builds, verifies, signs and uploads the patch.
flutter_ota patch android --channel staging
ota patch promote <patch_id> --percent 100   # staging -> production (Python admin CLI)

# 5. Open the app (it downloads and verifies the patch), then restart it.
# It now shows "Products (v2, with rating)". The APK was not reinstalled.

# 6. Undo.
flutter_ota rollback                         # the next start runs the store code again
```

To start again from v1, restore `packages/products` with `git checkout packages/products` and make
a new store release.

## Layout

| Path | What it is |
| --- | --- |
| [`lib/main.dart`](lib/main.dart) | `await FlutterOta.initialize()`, then the products feature and an OTA status line |
| [`lib/flutter_ota_features.g.dart`](lib/flutter_ota_features.g.dart) | Generated by `flutter_ota features generate`. The app reaches features only through it |
| [`packages/core`](packages/core) | Shared, host-owned code (config, theme). Part of the store build; never patched |
| [`packages/products`](packages/products) | The feature package. `ProductsFeature extends OtaFeature`. This is what a patch replaces |
| [`demo_api`](demo_api) | The demo's product API: `v1/` and `v2/products.json`, and `serve.sh` (port 8090) |
| [`demo_patch_v2/products`](demo_patch_v2/products) | The changed files of the demo patch. Copy them over `packages/products` |

## Regenerate the model code

After changing `packages/products/lib/src/data/product_model.dart`:

```bash
cd packages/products
flutter pub get
dart run build_runner build --delete-conflicting-outputs
```

The generated `*.freezed.dart` and `*.g.dart` files are committed.

## Notes

- **Platforms:** tested internally on **Android** (arm64) only. There is no iOS project; iOS is not
  supported.
- **OTA off by default:** a plain `flutter run` has no `FLUTTER_OTA_CONFIG`, so OTA is off and the
  app runs its own code. `flutter_ota release android` builds it with OTA on.
- **Cleartext HTTP:** the app allows `http://` only to `127.0.0.1` and `localhost` (the product
  API and a local test server through `adb reverse`). See
  `android/app/src/main/res/xml/network_security_config.xml`.
- The Android application ID is `dev.flutterota.ota_example`. Use your own application ID in your
  apps.
- The `android/` folder is a Flutter template project kept in Git so `flutter run` works without
  extra steps. It is not part of the published package.
